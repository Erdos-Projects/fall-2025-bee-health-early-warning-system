# Feature Engineering Summary

This document outlines the feature engineering process used to transform raw honeybee inspection and weather data into a model-ready dataset. The primary goal is to predict the `Healthy` status of a beehive based on its *previous* state and *recent* weather conditions.

## 1. Data Audit & Cleaning Summary

* **Target Variable:** The `Healthy` column (originally 'Yes'/'No') was converted to a binary integer (`1` for 'Yes', `0` for 'No') for modeling.

* **Missingness:** The raw `HCC_Inspections.csv` contained a small number of null values in `InsptDate` and the checklist columns (e.g., `Brood`, `Bees`). All rows with any null values were dropped to create a clean base dataset.

* **Duplicates:** The raw inspection data contained duplicate entries. These were removed. A critical de-duplication step was also performed on the weather data before the final merge to ensure that each inspection (defined by `HiveID` and `InsptDate`) had only one set of weather features.

* **Key Distributions:** Data originates from two distinct locations (NC and UT), which required using two separate weather files.

## 2. Dropped Features

Several features were dropped to prevent data leakage, reduce noise, and eliminate redundancy. This logic is primarily applied in `final_dataset.ipynb` as part of creating the lag features.

* **Dropped for Data Leakage:**

  * `Brood`, `Bees`, `Queen`, `Food`, `Stressors`, `Space`

  * **Justification:** These 6 checklist items are the *direct components* used to determine the `Healthy` target variable. Including them in a model to predict `Healthy` would be **data leakage** (i.e., giving the model the answer). The model must predict health based on *past* information, not current observations.

* **Dropped for Redundancy / Irrelevance:**

  * `InpsectionID`: A unique identifier with no predictive value.

  * `Hive_Tag`: A human-readable hive name, redundant with `HiveID`.

  * `Apiary`: A human-readable location name, redundant with `ApiaryID` and `City`/`State`.

  * `Percent_Met`: A direct calculation based on the 6 checklist items that were already dropped.

## 3. Engineered Features

New features were created to capture time-series dependencies (lag) and environmental context (weather).

### 3.1 Time-Series (Lag) Features

*(Created in: `final_dataset.ipynb`)*

* **Rationale:** The hive's *previous* state is a very strong predictor of its *current* state. These features shift the data from the prior inspection onto the current inspection's row.

* **Engineered Features:**

  * `Prev_Brood_Status`, `Prev_Bees_Status`, `Prev_Queen_Status`, `Prev_Food_Status`, `Prev_Stressors_Status`, `Prev_Space_Status`: The 1/0 status of each checklist item from the *previous* inspection.

  * `Prev_Health_Status`: The `Healthy` (1/0) status from the *previous* inspection.

### 3.2 Time-Series (Temporal) Features

*(Created in: `final_dataset.ipynb`)*

* **Rationale:** These features capture the context of *when* an inspection is happening relative to others for the same hive.

* **Engineered Features:**

  * `Days_Since_Last_Inspection`: The number of days that have passed since the hive's last check-up.

  * `Hive_Age_Days`: The "age" of the hive, calculated as the number of days since its *first-ever* inspection in the dataset.

  * `Is_First_Inspection`: A binary flag (`1` or `0`) that identifies the first inspection for a hive. This is important because a first inspection will have no "lag" data.

### 3.3 Weather Features

*(Created in: `weather_features.ipynb`)*

* **Rationale:** Bee health and behavior are heavily influenced by the external environment. We engineered features based on a **7-day trailing average**, as the weather in the week *leading up to* an inspection is most relevant.

* **Engineered Features:**

  * `Avg_prcp`, `Avg_wind`, `Avg_tmax`, `Avg_tmin`, `Avg_tavg`, `Avg_snow`: The 7-day average for precipitation, wind speed, max temp, min temp, average temp, and snow.

  * `Num_frost_days`: A 7-day *count* of how many days had a minimum temperature below freezing (32°F).

## 4. Generated CSV Datasets

This process created three key CSV files, with one being the final dataset for modeling.

1. **`final_weather_features.csv` (Intermediate)**

   * **Generated by:** `weather_features.ipynb`

   * **Includes:** Inspection keys (`HiveID`, `InsptDate`, `State`) joined with the 7 new engineered weather features (e.g., `Avg_tmax`, `Num_frost_days`).

2. **`target_markers_lagged.csv` (Intermediate)**

   * **Generated by:** `final_dataset.ipynb`

   * **Includes:** Inspection keys, the **target variable (`Healthy`)**, and all the engineered time-series features (e.g., `Prev_Health_Status`, `Days_Since_Last_Inspection`).

   * *Note: This file specifically excludes the current checklist items to prevent leakage.*

3. **`final_merged_dataset.csv` (Final Model-Ready Data)**

   * **Generated by:** `final_dataset.ipynb`

   * **Includes:** This is the final dataset, created by merging the two intermediate files above on `HiveID` and `InsptDate`. It contains the target (`Healthy`) and all engineered predictors (lagged and weather), ready for model training.
